# 병사 팀 → 분대장 앱 담당 AI 안내문 (2026-10-11, 확정판)

이 문서 하나로 분대장 앱(UNO Q)과 병사 팀의 구성과 방법을 통일한다. 병사 팀이 전달하는 문서는 이것뿐이다.

- **대상**: 분대장 앱을 맡은 AI. 당신이 쓴 계획서 `docs/squad_link_integration_plan.md`의 질문 1~8, 프로토콜 이슈 P1~P5, 코드 변경 C1~C7에 답한다.
- **기준 문서**: 레퍼런스 패키지 `soldier-node_ref_v1.1.zip`(이미 받아서 `~/work/soldier-node_ref_v1.1`에 풀어 둔 것)의 `docs/squad_ble_protocol_v1.md` v1.1, `docs/LEADER_INTEGRATION_GUIDE.md`, `docs/golden_vectors.json`
- **우선순위**
  1. 구성·역할 분담(누가 무엇을 하는가)은 **이 안내문이 우선**한다.
  2. 바이트·타이밍·규칙은 프로토콜 문서와 골든 벡터가 우선한다.
  3. 둘이 충돌하면 작업을 멈추고 병사 팀에 알린다.
- **레퍼런스 원본(zip, 풀어 둔 폴더)은 고치지 않는다.** 고칠 점은 병사 팀에 알린다.

## 1. 이렇게 정한 이유 (병사 팀 대화 요약)

- **보드 A는 원래 "맥은 광고를 못 낸다"는 이유로 만든 대체품이다.**
  - 맥의 CoreBluetooth는 Manufacturer Data를 담은 비연결형 광고를 낼 수 없다.
  - 그래서 개발 중에는 mock_leader가 USB로 보드 A에 명령을 넘기고, 보드 A가 광고했다.
- UNO Q는 리눅스(BlueZ)라 원칙적으로 직접 광고할 수 있다. 하지만 실제로 쓰기엔 걸리는 점이 많다.
  - 병사 연결을 유지하면서 광고와 스캔을 한 칩에서 동시에 해야 하는데, 이게 되는지 검증되지 않았다.
  - 당신이 확인했듯이 BT와 Wi-Fi가 같은 칩(Qualcomm WCN 계열)이고, AP도 2.4GHz다.
  - hcitool/btmgmt에는 sudo가 필요하다.
- **보드 A를 UNO Q USB에 꽂는 방법도 안 된다.**
  - UNO Q의 USB-C 하나는 동료 맥북에 상시 연결해야 한다(마이크 등).
  - 해커톤 현장이라 SSH도 쓸 수 없다.
  - 한 포트가 맥 쪽에서는 장치, 보드 A 쪽에서는 호스트가 되어야 해서 허브로도 해결되지 않는다.
- 결론: 프로토타입에서는 **기능을 물리적으로 나눈다.**
  - UNO Q는 연결 모드의 모든 것을 맡는다.
  - 보드 A는 분대장 위치 비콘과 침묵 방송(고정 명령)만 맡는다.

## 2. 구성과 역할

```
동료 맥북 ══ USB-C(상시: 마이크 등) ══ UNO Q ── BLE 연결(Central) ── 병사 보드 1 (SQ1-S1)
                                                                  └─ 병사 보드 B (SQ1-S2)
보드 A (배터리, 분대장 몸에 부착) ── BLE 비연결형 광고만 ──▶ 병사들 (UNO Q와는 아무 연결 없음)
```

### 2.1 보드 A가 하는 일
| 기능 | 동작 | 비고 |
|---|---|---|
| 분대장 위치 비콘 | 켜면 자동. 광고 `02 01 06 0B FF FF FF 01 20 <seq> 00 FF 02 FF FF`(BEACON 0x20, src 00, heading 없음 FFFF), 500ms 간격 계속 | 병사가 이 RSSI를 재서 RANGING의 **peer_id 0**으로 보낸다 = 분대장-병사 거리 |
| 버튼1 | HALT 정지, 긴급 | 모두 전원 대상(dst 1F), 비연결형 광고 100ms × 3초, LED1 3초 켜짐 |
| 버튼2 | TAKE_COVER 엄폐 270°(9시), 긴급 | 〃 |
| 버튼3 | CEASE_FIRE 사격 중지 | 〃 |
| 버튼4 짧게(1.5초 미만, 뗄 때 송신) | RALLY 집결 | 〃 (병사가 POS_TABLE로 분대장 방향 계산) |
| **버튼4 길게(1.5초 이상, 누르는 중 송신)** | **EMCON_SET 2 = 침묵 해제** `01 16 <seq> 00 1F 01 02` | **이번 추가 기능. 보드 A 업로드 후부터 동작(§4)** |

- seq는 보드 A가 부팅할 때마다 무작위로 시작해 1씩 늘린다. 명령 방송 3초 동안은 비콘이 멈췄다가 다시 켜진다.
- **보드 A의 위치가 곧 분대장 원점(0,0)이다.** 반드시 분대장 몸(UNO Q 옆)에 붙인다.
- 보드 A가 이번에 하지 않는 일(USB가 있어야 되는 기능): 임의 명령·EMCON_SET 1 방송, 병사 비콘 RSSI 출력(`BCN`), 비콘 on/off.
  - 레퍼런스 가이드 §b·§c·§d의 `--beacon-port`, `bcmd`, `bemcon`, `lbeacon`, `BCN`, "분대장 줄"은 **이번 구성에서는 해당 없음**이다.
  - 레퍼런스 zip 안 가이드 §d의 보드 A 버튼 설명에는 버튼4 길게가 없다. **이 표가 최신**이다.

### 2.2 UNO Q 앱이 구현할 것
프로토콜 §0.1 체크리스트 중 **8번(침묵 방송)을 뺀 전부**다. 분대장 위치 비콘 송출도 하지 않는다.

- `SQ1-S1`~`S5` 이름 필터 스캔 → 연결 → NUS TX Notify 구독 → MTU 확보 → 끊기면 자동 재연결(침묵 중에도 재연결 루프는 계속 돈다)
- CMD_BUTTON 송신, 대상별 ACK/CANNOT_COMPLY 수집, **15초 무응답이면 같은 seq·같은 바이트로 1회 재전송**, 그래도 없으면 미수신 알림
- 음성 명령: VOICE_BEGIN/CHUNK/END(8kHz IMA ADPCM, 청크 간격 15ms), VOICE_RESULT 처리. **침묵 모드에서는 보내지 않는다.**
- EMCON_SET(0~2), REQ_STATS → STATS
- 병사 보고(0x01~0x0B) 수신 → 사람이 읽는 문장 → **RPT_ACK 즉시 자동**(재전송을 받아도 다시 보냄)
- PEER_REPORT 중계: dst = 보고자를 뺀 병사들, **끝에 orig_seq**, 위치를 모르면 rx/ry = `0x8000`, 재전송된 보고는 다시 중계하지 않음
- RANGING 수집 → 거리 → MDS → 방향 정렬 → POS_TABLE(분대장 id 0 = (0,0) 포함)
- 무시해도 되는 것: 0x7F LOG(EMCON 2에서 계속 옴. 별도 창 권장), 병사 직접 방송 광고, 병사 비콘

### 2.3 UNO Q가 하지 않을 것
- 비연결형 광고(침묵 방송, 분대장 비콘), 병사 비콘 스캔, hcitool/btmgmt/D-Bus 광고, sudo
- 보드 A 시리얼(`/dev/ttyACM*`, DTR, `OK tx`/`DONE`/`BCN`)

## 3. 핵심 흐름

### 3.1 침묵 모드(EMCON 0) 시연
1. UNO Q가 연결 상태에서 `EMCON_SET 0` 또는 `CMD_BUTTON SILENCE(0x0B)`를 보낸다.
   - 병사들은 연결을 끊고 수동 스캔에 들어간다.
   - UNO Q 쪽에서는 병사가 사라지는 것이 정상이다.
2. 침묵 중 명령은 분대장이 **보드 A 버튼1~4**로 방송한다.
   - UNO Q는 이 동안 병사와 통신할 수 없다.
   - 병사가 버튼으로 보낸 ACK는 병사 큐에 저장된다.
3. 침묵 해제는 분대장이 **보드 A 버튼4를 1.5초 이상** 누른다(EMCON_SET 2, 전원).
   - 병사가 직접 풀 수도 있다(조이스틱 1초 길게 또는 버튼1+버튼2 2초, 0→1→2 순환).
   - EMCON_SET 방송은 **침묵(EMCON 0)인 병사만** 받아들인다. 이미 풀린 병사는 무시한다.
   - 3초 방송을 놓친 병사가 있으면 다시 누른다. 새 seq로 나가며 해롭지 않다.
4. 병사가 연결 가능 광고를 다시 시작한다 → UNO Q 자동 재연결 → 병사가 EMCON_STATE(0x0B, mode 2)를 보내고 큐에 쌓인 보고·ACK를 오래된 순서로 보낸다(확인 응답이 먼저).
5. 분대장 비콘은 침묵 중에도 계속 나간다. 프로토타입에서는 그대로 두고, 엄밀하게 하려면 보드 A 전원을 끈다(그러면 해제 버튼도 못 쓰므로 병사가 직접 해제).

### 3.2 위치 계산
- 입력은 병사들의 RANGING(0x0E)뿐이다.
  - 병사 i가 보낸 peer j 값이 병사 사이 거리다.
  - **peer 0 값이 분대장(보드 A)-병사 거리**다.
- RANGING은 병사가 **EMCON 2이고 분대장과 연결 중일 때** 10초마다 온다. 병사끼리 재는 병사 비콘도 같은 조건에서만 나간다. 그래서 위치 계산은 전원이 EMCON 2로 연결된 상태에서, 30초 이상 기다린 뒤 한다.
- 레퍼런스 `squad_localize.py`를 그대로 옮기면 된다.
  - `measured_from_rssi(rows, -65.5, 1.6)`에 병사 줄만 넣는다. 분대장 줄 `rows[0]`은 없어도 된다. 한 방향 값만 있는 쌍은 그 값을 쓰고, 양쪽 값이 있으면 평균을 낸다.
  - 그다음 `localize(ids, measured, clocks=DEFAULT_CLOCKS)` → `to_pos_table` 순서다.
  - 30초 넘은 RANGING은 버린다. 피어별 값은 병사가 이미 중앙값으로 보낸다.
- 방향 정렬 기본값은 `DEFAULT_CLOCKS = {1: 10, 2: 2}`다. 분대장 총구가 북쪽이고, S1은 왼쪽 앞 10시, S2는 오른쪽 앞 2시다. 거리만으로는 회전·반사를 정할 수 없어서, 분대장이 본 대략적인 방향으로 맞춘다.

### 3.3 UNO Q가 직접 거리를 재지 않는 이유 (D4)
- UNO Q도 bleak로 병사 비콘(0x20)을 스캔해 RSSI를 받을 수는 있다. 하지만 이번에는 하지 않는다.
  - **칩이 다르다.** 병사·보드 A는 nRF52840이고 UNO Q는 Qualcomm WCN 계열이다. 안테나와 수신 감도가 달라 같은 거리에서도 RSSI가 몇 dB씩 다르다. 지금 보정값(−65.5/1.6)은 nRF끼리 잰 값이라 UNO Q 값에 그대로 쓰면 거리가 틀어진다.
  - 병사 연결을 유지하면서 스캔까지 하면 칩 부하가 늘고, Wi-Fi와 같은 칩이라 끊김 위험이 커진다.
  - BlueZ 중복 필터 때문에 RSSI 표본이 듬성듬성 올 수 있다.
  - peer 0만으로도 분대장 거리는 이미 들어온다.
- 시간이 남아서 선택 과제로 하게 되면 **UNO Q용 경로손실 보정(1·3·5m)을 따로** 하고, 그 값을 분대장 줄 `rows[0]`에 넣는다. 하기 전에 병사 팀과 먼저 합의한다.

- **업로드 전 펌웨어와 레퍼런스 소스의 차이**(지금 보드로 시험하면 이 부분이 문서와 다를 수 있다. 앱 버그가 아니다):
  - 보드 1·B
    - 거리 v1.0.4(10·20·40m, 구간 경계 15/30m)가 아직 반영되지 않았다. 다른 병사 보고를 내 기준으로 바꾼 문장의 거리 구간이 앱 계산과 다를 수 있다.
    - 보고 큐 3종 분류, EMCON 1에서 재연결 시 즉시 송신, 2→1 일괄 송신 없음도 아직 없다.
  - 보드 A: 버튼4 길게(EMCON_SET 2)가 없다. 지금은 버튼4를 누르는 순간 집결이 나간다.
- 업로드하는 동안(보드당 수 분) 해당 보드는 꺼졌다 켜진다. 재연결 루프가 있으면 신경 쓰지 않아도 된다.
- **수락 시험(가이드 §h) 최종 판정은 업로드 뒤에 한다.** 그 전에는 연결, 명령, ACK, 보고, RPT_ACK, STATS, POS_TABLE 왕복 위주로 시험한다.

## 5. 입력 → CMD_BUTTON 매핑 (입력 방식은 자유, 결과는 이 규칙)

프레임 = 헤더 `01 10 <seq> 00 <dst> 06` + payload 6바이트(리틀 엔디언).

| 필드 | 값 | 규칙 |
|---|---|---|
| dst_mask(헤더) | 전원 `1F`, S1 `01`, S2 `02`, S1+S2 `03` … | bit(ID−1). **대상 병사의 연결로만 write**한다 |
| cmd_code | 01 HALT, 02 TAKE_COVER, 03 ADVANCE, 04 WITHDRAW, 05 RALLY, 06 OPEN_FIRE, 07 CEASE_FIRE, 08 OBSERVE, 09 ENEMY_INFO, 0A REPORT_STATUS, 0B SILENCE, 0C HOLD, 0F CANCEL | 13종(프로토콜 §6) |
| azimuth u16 | 분대장 기준 시계 c → `(c × 30) mod 360`(12시 → 0, 9시 → 270), 방향 없으면 `FFFF` | 분대장 방위 0 고정. **RALLY는 항상 FFFF**(병사가 계산) |
| dist_band u8 | 근 0 / 중 1 / 원 2 / 없음 `FF` | 대표값 10·20·40m |
| extra u8 | ENEMY_INFO 적 수(0 미상, 1~4, 5 다수), 그 외 0 | |
| priority u8 | 0 일반 / 1 긴급 | |

- 방향이 꼭 필요한 명령: OPEN_FIRE, OBSERVE, ENEMY_INFO. 방향을 넣어도 되는 명령: TAKE_COVER, ADVANCE, WITHDRAW. 나머지는 `FFFF`.
- 예: "전원 9시 엄폐 긴급" → `01 10 <seq> 00 1F 06 02 0E 01 FF 00 01`
- 예: "S2 적 3명 2시 원거리" → `01 10 <seq> 00 02 06 09 3C 00 02 03 00`
- 키패드 배치 초안(A 보고 / B 교범 질문 / C 병사 하달 PTT / D 대상 순환 / 숫자 명령 / `#` 송신 / `*` 취소 / 숫자 길게 = 방향)은 그대로 진행해도 된다. 강제 사항은 없다.
  - v1.1에서 예전 §6.3 "분대장 입력 장치 권장안"(4×4 키패드 + 조이스틱)은 빠졌다.
- 음성 명령(PTT 녹음 → 8kHz → IMA ADPCM)은 CMD_BUTTON과 별개 경로다.

## 6. 질문 1~8 답변

1. **bleak**: venv의 3.0.2로 진행한다.

2. **보드 A를 UNO Q USB에 연결**: 하지 않는다(D1). 허브도 필요 없다.
3. **C1~C7**
   - 병사 팀 입장에서 **C1(거리 10·20·40m, 구간 경계 15/30m, 없음 = 20m)과 C2(시계 변환, §7.1)는 필수**다.
   - C3~C7은 "v1.1·이 안내문과 충돌하는가"를 기준으로 판단한다. 충돌하면 v1.1을 따른다.
   - 기존 코드 변경의 최종 승인은 당신 쪽 담당자(사람)가 한다.
4. **분대장 방위**: 0(북쪽) 고정(D5). GPS나 이동 모의값은 쓰지 않는다. POS_TABLE heading 필드는 병사가 쓰지 않으므로 0으로 둔다.
5. **키패드**: 입력 방식은 자유(D6, §5). 배선 핀과 `msgpack` 설치 승인은 당신 쪽 담당자가 정한다(병사 팀 무관).

7. **소대장 보고 형식(sq-rpt/0.1)**: 분대장 ↔ 소대장 구간은 병사 팀이 관여하지 않는다. 기존 초안을 써도 된다.
8. **sudo / BlueZ 광고**: 필요 없다(D2). 계획에서 이 단계를 뺀다.

## 7. 프로토콜 이슈 P1~P5 답변

- **P1 seq 시작값**
  - 운용에서는 **무작위 시작**을 쓴다. 새 명령마다 seq를 바꾸고, 재전송만 같은 seq·같은 바이트로 한다.
  - mock_leader는 seq를 0부터 쓴다(`mock_leader.py:255`).
  - "로그 hex 동일" 비교는 **헤더 offset 2(seq) 바이트를 빼고** 하거나, 앱에 시험용 `--seq-start N` 옵션을 둔다(권장).
  - 병사의 RPT_ACK ref_seq와 ACK의 ref_id에는 앱이 보낸 seq가 그대로 돌아온다.
  - 보드 A도 src 00이라 seq가 겹칠 수 있지만 문제없다. 병사는 **(src, seq, payload CRC)가 60초 안에 같을 때만** 중복으로 본다. 중복이면 다시 재생만 하고, 마지막 재생 후 5초 안이면 무시한다.
- **P2 반올림**
  - 기준은 **0에서 먼 쪽(half away from zero)**이다. 병사 펌웨어 C가 이렇게 한다.
  - 레퍼런스 Python의 `round()`(짝수 쪽 반올림, `squad_localize.bearing_range`·`to_pos_table`)는 레퍼런스 쪽 결함이다. 따라 하지 않는다.
  - 골든 벡터에는 정확히 .5인 경우가 없어서 두 방식 모두 통과한다.
  - 방위 → 시계 변환은 반올림 함수를 쓰지 않는다(§7.1).
- **P3 경로손실**
  - **P1m = −65.5 dBm, n = 1.6**을 쓴다(2026-10-11 현장 잠정 보정, nRF 대 nRF).
  - 레퍼런스 `squad_localize.rssi_to_m` / `measured_from_rssi`의 **기본 인자 −59/2.0은 갱신되지 않은 옛 값**이다. mock_leader는 −65.5/1.6을 명시해서 넘겼기 때문에 문제가 없었다.
  - 앱에서는 기본 인자에 기대지 말고 설정 상수로 명시한다. 현장에서 바꿀 수 있게 둔다.
- **P4 보드 A DTR**: 해당 없음(USB 미사용).
- **P5 분대장 방위**: 0 고정(D5).

### 7.1 시계 변환 (C2, 골든 벡터 `clock_from_azimuth` / `azimuth_from_clock`)
- 방위 → 시계: `rel = (az − heading + 360) % 360; clock = (rel + 15) // 30`(정수 나눗셈), 0이면 12.
  - **az == 0xFFFF → clock 0(방향 없음).**
  - heading == 0xFFFF → heading 0으로 간주.
  - 경계 예: 15° → 1시, 345° → 12시.
- 시계 → 방위: `az = (heading + (clock − 12) × 30) mod 360`. **clock 0이거나 heading 0xFFFF이면 → 0xFFFF.**

## 8. 시험 순서

**지금 할 수 있는 것 (업로드 전 보드)**
1. 병사 팀이 mock_leader를 끈다. 보드 1·B는 켜 둔다. 보드 A는 켜서 분대장 옆에 둔다.
2. UNO Q: `SQ1-S1`, `SQ1-S2` 스캔 → 연결 → Notify 구독 → **MTU 출력**.
   - 현장에 장치가 400대 넘게 보이므로 이름 필터는 필수다.
   - BlueZ에서 스캔 중 연결이 `InProgress`로 실패하면 스캔을 멈추고 연결한 뒤 재개한다(가이드 §f-2).
3. 병사가 버튼으로 보고 → 앱이 문장을 표시하고 RPT_ACK를 보낸다.
   - 병사는 "적 송신"·"송신"을 듣는다. 긴급 보고는 RPT_ACK를 받으면 "수신"도 듣는다.
   - 소리는 병사 팀이 듣고 확인한다.
4. CMD_BUTTON("전원 9시 엄폐 긴급") → 병사 재생 → 병사 버튼3 짧게 → ACK. 길게 누르면 CANNOT_COMPLY다.
5. REQ_STATS → STATS.
6. 전원 EMCON 2로 연결된 채 30초 이상 기다린다 → RANGING(peer 0 포함) 수집 → 위치 계산 → POS_TABLE → 병사 RALLY 방향 재생 확인.
7. 침묵: EMCON_SET 0 → 보드 A 버튼1~3으로 명령 → 병사가 직접 해제(업로드 전에는 버튼4 길게가 없다) → 자동 재연결 → 큐에 있던 ACK 수신.

**업로드 뒤 (병사 팀 알림 후)**
8. 7번을 보드 A 버튼4 길게로 해제하는 방식으로 다시 한다.
9. 가이드 §h 수락 시험 1~16을 한다. 그중 보드 A USB가 필요한 항목(앱에서 하는 침묵 방송, BCN, 비콘 on/off)은 이 안내문 §2.1·§3.1 방식으로 바꾸거나 건너뛴다.
10. 다른 병사 보고 중계(PEER_REPORT)의 거리 구간이 10·20·40m 기준으로 맞는지 확인한다.

## 9. 병사 팀에 알릴 때

- 형식: "단계 N에서 (보낸 hex) → (받은 hex 또는 현상) / 기대값(문서 §·골든 벡터 항목)"
- 레퍼런스 결함으로 보이면 고쳐 쓰지 말고 알린다. 이미 알려진 것은 P2(`round`), P3(기본 인자)다.
- 병사 팀이 이 안내문의 결정(보드 A 독립, 버튼4 길게, P1~P5 답)을 다음 레퍼런스 판에 반영할 예정이다. 그때까지는 **이 안내문이 최신**이다.
