# 작업 지시: 분대장 앱에 "분대-병사 링크" 기능 추가

이 문서는 분대장 앱 저장소에서 작업하는 코딩 AI(Claude Code)에게 주는 작업 지시다.
사람(분대장 담당)이 이 파일을 저장소의 `docs/LEADER_TASK.md`에 두고 "docs/LEADER_TASK.md를 읽고 S0부터 진행해줘"라고 지시한다.

## 배경

- 이 저장소는 우리 팀의 분대장 앱(Arduino UNO Q)이다. 이미 STT, TTS, 소대장과의 통신이 있다.
- 팀원이 병사 노드(NU-40 DK, nRF52840 BLE) 펌웨어를 완성했다. Mac에서 도는 흉내용 분대장(`tools/mock_leader.py`)과 보드 A(분대장 광고 대행 NU-40)로 실기 시험도 통과했다.
- 이제 그 흉내용 분대장이 하던 일 전부를 이 앱 안에서 하도록 기능을 추가한다. 연결과 보고 수신, 명령·음성 하달, EMCON 전환, 침묵 방송, 보고 중계, 거리 측정, 위치 계산과 위치표 배포가 모두 포함된다.
- 병사 쪽 레퍼런스 패키지 경로: `<REF_PATH>`(예: `~/work/soldier-node_ref_v1.1`). 사람이 실제 경로로 바꿔 둔다.

## 절대 규칙

1. `<REF_PATH>`는 읽기 전용이다. 수정하지 않고, 이 저장소 안으로 통째로 복사하지도 않는다.
2. `<REF_PATH>/CLAUDE.md`는 병사 팀 내부 작업 규칙이다. 너에게는 적용되지 않는다. 참고 자료로만 읽는다.
3. 병사와의 통신, 프로토콜, 타이밍, 거리 측정, 위치 계산의 유일한 기준은 `<REF_PATH>/docs/squad_ble_protocol_v1.md`(v1.1)와 레퍼런스 코드다. 우리 쪽 편의로 바꾸지 않는다.
   불일치나 모호한 점을 발견하면 임의로 정하지 말고 "프로토콜 이슈"로 기록해 사람에게 묻는다. 병사 팀이 확인한다.
4. 레퍼런스 코드를 포팅할 때는 파일 상단에 원본 경로를 적는다. 그리고 `<REF_PATH>/docs/golden_vectors.json`의 모든 항목(frames, advertising, crc16, adpcm, 시계 변환, peer_to_me, pathloss, rssi_median, localize)을 통과하는 테스트로 바이트 단위 동일성을 증명한다.
5. 기존 기능(STT, TTS, 소대장 통신, UI)은 깨뜨리지 않는다. 기존 코드를 바꿔야 하면 바꾸기 전에 이유와 범위를 설명하고 승인을 받는다.
6. 각 단계가 끝나면 멈추고 보고한 뒤 사람의 확인을 받는다. 확인 없이 다음 단계로 넘어가지 않는다.
7. 하드웨어와 OS에 관한 사실은 가정하지 않고 명령 출력으로 확인한다. sudo나 시스템 설정 변경, 패키지 설치는 실행 전에 사람의 승인을 받는다.

     - 시연 안정성이 우선이다. (a)가 검증되기 전에는 (b)를 기본 경로로 둘 것을 권장한다.

## S1. 프로토콜 코어 (BLE 없이)

- 대상: 모든 메시지 타입의 인코드/디코드, 광고 AD 데이터 생성과 파싱, CRC-16/CCITT-FALSE, IMA ADPCM 인코드, dedup(병사·seq·바이트 동일·60 s), 분대장 seq(무작위 시작, 재전송은 같은 seq·같은 바이트), 시계 변환, 경로손실 거리, RSSI 중앙값, 위치 복원(MDS·정렬·POS_TABLE).
- 이 앱이 Python이면 레퍼런스 모듈을 런타임에 import하지 말고 이 저장소로 포팅한다(레퍼런스 폴더가 없어도 앱이 돌아야 함).
- 통과 기준: golden_vectors.json 전 항목 통과 테스트.

## S2. 병사 1대 링크

1. 먼저 UNO Q에서 레퍼런스 `mock_leader.py`를 그대로 돌린다(정답 비교용).
   - 병사 1대 연결, 보고 수신, RPT_ACK, 명령 → ACK까지 확인한다.
   - BlueZ 권한, MTU(가이드 f-1), 스캔 중 연결 실패(f-2) 문제는 여기서 해결한다.
2. 이 앱의 링크 모듈로 같은 일을 구현한다: 스캔(이름 `SQ1-S1`~`S5` + NUS UUID), 연결, MTU 확보, notify 구독, 끊김 감지, 자동 재연결, `pending_acks` 처리.
- 통과 기준: 같은 조작에서 mock_leader의 `--log-csv`와 이 앱 로그의 송수신 hex가 같다.

## S3. mock_leader 기능 동등성

가이드 b항 표의 모든 기능을 구현한다(map·dist·mark 같은 화면·보정용 기능은 이 앱의 UI·로그 방식에 맞춰). 최소 범위는 다음과 같다.

- 병사 2대 이상 동시 연결
- 병사별 상태: 연결, EMCON, 마지막 보고, 미확인 명령, 위치, 마지막 통신 시각
- 보고 수신(0x01~0x0B, STATS, RANGING): 즉시 RPT_ACK(RANGING·LOG는 제외), 중복 판정은 가이드 f-4 권장 방식
- CMD_BUTTON: 대상 비트, 15초 무응답 대상에 같은 바이트로 1회 재전송, 이후 "미수신"
- 음성 하달: VOICE_BEGIN/CHUNK/END. VOICE_RESULT ≠ 0이면 같은 voice_id로 1회 재전송. 쓰기 방식(제어는 with response, 청크는 without response)과 `len ≤ MTU−3`
- EMCON_SET(연결 write), 침묵 중 방송 명령과 EMCON 복귀(S0에서 승인된 송출 방식)
- PEER_REPORT 중계(orig_seq 포함, 위치표 없으면 0x8000)
- REQ_STATS/STATS
- 송수신 전체 로그(CSV 또는 JSONL)
- LOG 0x7F는 표시와 기록만
- 통과 기준: 가이드 h항 수락 시험 1~9, 12 재현. 결과를 표로 보고한다.

## S4. 거리 측정과 위치

- 분대장 비콘(ID 0) 상시 송출(침묵 방송 3초 동안 일시 중단)
- 병사 비콘 RSSI 수집(분대장 줄), 병사 RANGING 수집
- N×N 거리행렬, MDS, 시계 방향 정렬, POS_TABLE 송신
- 프리셋 대형(wedge·line·column, 10 m)과 거리 직접 입력 예비 경로
- 경로손실 기본값 P1m −65.5 dBm, n 1.6(설정으로 변경 가능), 보정 절차(fit_pathloss) 지원
- 위치 규칙: (0,0) 금지, 모름은 0x8000
- 통과 기준: 같은 입력에 대해 squad_localize.py와 같은 출력, 가이드 h항 10·11·13~16 재현

## S5. 기존 기능과 연동

> 2026-10-11 사용자 지시로 변경: **소대장 ↔ 분대장과 분대장 ↔ 병사는 프로토콜·통신 기능을 완전히 분리**한다. 원래의 "병사 보고 → 소대장", "소대장 지시 → 병사" 항목은 삭제했다.
> 병사 보고는 분대장에게 전달되고(헤드셋) 전투 로그에 저장된다. 소대장에게는 **분대장이 정형화된 보고서를 보낼 때만** 그 보고서 안에 적절히 반영되어 간다(자동 전달 없음).
> 분대원 위치는 소대장 화면에 계속 표시한다. 병사와 소대장은 직접 연결되지 않으므로, 분대장이 받은(계산한) 분대원 위치를 분대장이 소대장에게 중계한다.

1. 병사 보고 → 분대장
   - 가이드 e항 문장 규칙으로 한국어 문장을 만든다.
   - 기존 TTS로 분대장 헤드셋에 재생한다. CASUALTY_SELF는 최우선으로 2회.
   - 화면과 로그에도 표시한다.
   - LLM 요약을 쓰더라도 템플릿 문장을 기본으로 둔다(LLM 없이도 동작).
2. 병사 보고 → 전투 로그·보고서 재료: 받은 병사 보고(원 프레임과 해석, 수신 시각)를 전투 로그에 저장하고 분대장 상황 정리(적 표적·아군 현황)에 넣는다. 소대장에게 따로 보내지 않고, 분대장이 정형화된 보고서를 보낼 때만 그 안에 반영된다.
3. 분대장 음성(STT) → 병사
   - 정해진 명령어(정지, 엄폐+방향, 사격 중지, 집결 등 프로토콜 CMD 코드)는 CMD_BUTTON으로 보낸다.
   - 그 외는 기존 TTS 음성을 8 kHz 모노 16비트로 변환해 ADPCM 음성 하달로 보낸다.
   - 대상 지정(전원/N번)을 지원한다.
   - EMCON 상태에 따라 경로를 고른다: 연결 송신 또는 침묵 방송. 침묵 중에는 CMD_BUTTON과 EMCON_SET만 가능하고 음성은 불가하다. 침묵 중 음성을 요청하면 이 사실을 분대장에게 알린다.
4. 미확인 명령: 재전송 후에도 ACK가 없으면 분대장에게 "N번 미수신"을 알린다. 이후 조치는 분대장이 결정한다.
5. EMCON 전환 명령을 분대장이 음성이나 UI로 내릴 수 있게 한다.
- 통과 기준: 데모 시나리오 1회 완주.
  보고 → 분대장 청취 → 전투 로그 저장 → (분대장 정형 보고에 반영) → 음성 명령 → 병사 ACK → 침묵 전환 → 침묵 중 방송 명령 → 정상 복귀와 재연결 → 쌓인 보고 수신 → 위치표 → 중계 보고 "N번 쪽" 확인.
