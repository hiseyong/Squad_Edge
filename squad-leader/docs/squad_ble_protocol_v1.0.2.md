# 분대 BLE 통신 명세 v1.0.2 (병사 단말 ↔ 분대장 단말)

> 대상 독자: 병사 단말(NU-40 DK) 담당, 분대장 단말(Arduino UNO Q) 담당, 그리고 각자 사용하는 코딩 AI.
> 이 문서가 두 단말 간 통신의 **유일한 기준**이다. 이 문서와 다르게 구현해야 하면 먼저 팀에 공유하고 문서를 고친다.
> 모든 다바이트 정수는 **리틀엔디언**. 모든 각도는 **도(degree), 진북 기준 시계방향 0~359**.

---

## 0. 요약

| 항목 | 결정 |
|---|---|
| 병사 단말 | NU-40 DK (nRF52840), BLE Peripheral + (침묵 모드 시) Passive Scanner |
| 분대장 단말 | Arduino UNO Q (Linux, BlueZ), BLE Central + Broadcaster |
| 연결 모드 채널 | Nordic UART Service(NUS) 위에 자체 프레임 |
| 침묵 모드 채널 | 분대장 광고(Manufacturer Specific Data) → 병사 수동 스캔. 병사는 송신 0 |
| 분대장 → 병사 | ① 음성 명령(ADPCM 압축 음성, 연결 모드 전용) ② 버튼 명령(코드, 연결/침묵 모두) |
| 병사 → 분대장 | 보고 코드(적 발견, 징후, 상태, 수신 확인 등) |
| 방향 표현 | 무선 구간에서는 항상 **절대 방위**. "몇 시 방향" 변환은 **받는 쪽**에서 자기 방위 기준으로 수행 |
| 분대 구성 | 분대장 ID 0, 병사 ID 1~5 |

## 1. 장비와 역할

### 1.1 병사 단말
- NU-40 DK, 9축 방위 센서(Qwiic I2C), 조이스틱(A1/A2 + SW, 3.3V 전원), 이어폰(PWM 오디오 출력), 배터리.
- 입력: 온보드 버튼 4개 + 조이스틱(기울임 + 누름).
- 출력: 이어폰 음성(내장 음성 조각 재생 또는 수신 음성 재생), LED 4개.

### 1.2 분대장 단말
- Arduino UNO Q 4GB, 헤드셋(마이크+이어폰), GPS 모듈, 방위 정보(방위 센서 또는 GPS 진행 방향), 버튼 명령 입력 장치(§6.3).
- 음성 명령: 마이크 녹음 → ADPCM 인코딩 → 병사에게 전송.
- 버튼 명령: 키 입력 → 명령 코드 → 병사에게 전송.
- 병사 보고 수신 → 분대장 헤드셋으로 읽어주기, 소대장 보고용 데이터로 저장(분대장 측 범위, 이 문서 밖).

## 2. 통신 모드 (EMCON, 전파 방출 통제)

| 모드 값 | 이름 | 링크 | 병사 송신 | 분대장 → 병사 가능 메시지 |
|---|---|---|---|---|
| 0 | 침묵 SILENT | 연결 없음. 분대장 광고 → 병사 수동 스캔 | **없음** (보고는 큐에 저장) | 버튼 명령만 |
| 1 | 최소 MIN | NUS 연결 | 긴급 보고와 ACK만 즉시, 나머지는 30초 묶음. 송신 출력 최저 | 버튼 명령, 음성 명령 |
| 2 | 정상 NORMAL | NUS 연결 | 즉시 | 버튼 명령, 음성 명령 |

규칙
- 병사는 조이스틱 길게 누르기로 자기 모드를 바꿀 수 있다. 분대장은 `EMCON_SET` 명령으로 병사 모드를 바꿀 수 있다(§6.2 코드 0x0B, 또는 §5.2 0x16).
- 침묵 모드 진입 시 병사는 **연결을 끊고 광고를 중지**한 뒤 **수동 스캔**(active scan 금지, scan request를 보내지 않음)만 한다.
- 침묵 모드에서 생긴 보고는 병사 RAM 큐(최대 32건)에 보관하고, 모드 1/2로 돌아오면 연결 후 오래된 순서로 송신한다. 큐가 넘치면 일반 보고부터 버리고 긴급 보고는 유지한다.
  - (v1.0.1) 큐가 긴급 보고만으로 가득 찬 경우: 새 일반 보고는 버리고, 새 긴급 보고가 오면 **가장 오래된 긴급 보고를 버린다**(최신 상황 우선).
- 침묵 모드에서는 수신 확인(ACK)도 큐에 넣는다. 분대장은 침묵 모드에서 ACK를 기대하지 않는다(시야 확인).
- 음성 명령은 침묵 모드에서 보내지 않는다.

## 3. BLE 계층

### 3.1 연결 모드 (EMCON 1, 2)
- 병사 = Peripheral(GATT 서버). 광고 이름: `SQ1-S{id}` (예: `SQ1-S1`). 분대 번호 1 고정(v1).
- 분대장 = Central. 병사 최대 5대에 각각 연결.
- 서비스: Nordic UART Service
  - Service UUID: `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
  - RX 특성(분대장 → 병사, Write / Write Without Response): `6E400002-B5A3-F393-E0A9-E50E24DCCA9E`
  - TX 특성(병사 → 분대장, Notify): `6E400003-B5A3-F393-E0A9-E50E24DCCA9E`
- MTU: 병사는 최대(247)를 허용하도록 설정한다. 분대장은 협상된 MTU를 읽고 **한 번의 write 최대 길이 = MTU − 3**을 넘지 않는다. 협상 실패 시 20바이트로 가정하고 동작해야 한다(음성은 느려짐).
- 하나의 GATT write/notify = 하나의 프레임(§4). 프레임을 여러 write로 쪼개지 않는다(음성은 §7의 청크 단위로 이미 쪼개져 있음).
- 버튼 명령과 보고는 Write **With** Response(링크 수준 전달 보장), 음성 청크는 Write **Without** Response(속도).
- 병사 TX Notify는 분대장이 CCCD를 켜야 동작한다. 분대장은 연결 직후 반드시 Notify를 구독한다.

### 3.2 침묵 모드 (EMCON 0): 광고 방송
- 분대장이 Legacy Advertising(Non-connectable)으로 송신.
- AD 구조: Flags(3바이트) + Manufacturer Specific Data.
  - Company ID: `0xFFFF` (테스트 용도 예약값. 실제 제품에서는 정식 ID로 교체)
  - 그 뒤 데이터 = §4 프레임 그대로(헤더 6 + 페이로드). 31바이트 한도 안에 들어가야 하므로 **CMD_BUTTON(§6, 12바이트)과 EMCON_SET(§5.2 0x16, 7바이트) 프레임만** 허용. (v1.0.2: EMCON_SET 추가 — 침묵 중인 병사를 방송으로 연결 모드로 되돌리기 위함. §5.2 표와 일치)
- 분대장은 같은 프레임을 **광고 간격 100ms로 3초간 반복**한 뒤 광고를 멈춘다.
- 병사는 Company ID `0xFFFF` + 프레임 `ver=0x01` + `src_id=0`인 광고만 받아들이고, `(src_id, seq)`로 중복을 제거한다(최근 16개 기억).
  - (v1.0.2) 같은 (src_id, seq)가 **5초 안에** 다시 오면 방송 반복으로 보고 조용히 버린다(재생하지 않음). 5초가 지난 뒤 같은 seq가 오면 분대장 재전송으로 보고 다시 재생만 한다(§8.1-6).
- 병사는 침묵 모드에서 이 광고의 RSSI도 기록할 수 있다(위치 추정 참고값, v2).

## 4. 공통 프레임 형식

모든 메시지(연결 모드의 write/notify, 침묵 모드의 광고 데이터)는 다음 형식이다.

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0 | 1 | ver | `0x01` 고정. 다르면 폐기 |
| 1 | 1 | msg_type | §5 메시지 종류 |
| 2 | 1 | seq | 송신자별 순번 0~255 순환. 송신자가 프레임마다 +1 (재전송 시 같은 값 유지) |
| 3 | 1 | src_id | 0 = 분대장, 1~5 = 병사 |
| 4 | 1 | dst_mask | bit0~bit4 = 병사 1~5, bit7 = 분대장. `0x1F` = 병사 전원, `0xFF` = 모두 |
| 5 | 1 | len | 뒤따르는 페이로드 길이(바이트) |
| 6 | len | payload | 메시지별 형식 |

- 수신자는 `dst_mask`에 자기 비트가 없으면 폐기한다(병사 ID n → bit(n−1)).
- `len`이 실제 길이와 다르면 폐기한다.
- 공통 필드 값 표기:
  - azimuth(uint16): 0~359 절대 방위, `0xFFFF` = 방향 없음/미상
  - dist_band(uint8): `0` 근거리(대표값 50m), `1` 중거리(100m), `2` 원거리(200m 이상, 계산 대표값 200m), `0xFF` 없음
  - heading(uint16): 송신자 자신의 현재 방위(총구/정면), `0xFFFF` = 센서 없음

## 5. 메시지 종류 목록

### 5.1 병사 → 분대장 (TX Notify, `dst_mask = 0x80`)

| msg_type | 이름 | 긴급 | payload |
|---|---|---|---|
| 0x01 | CONTACT 적 발견 | 예 | azimuth(2) clock(1) dist_band(1) count(1) heading(2) = 7 |
| 0x02 | SUSPICIOUS 의심 징후(소리·움직임) | 아니오 | azimuth(2) clock(1) heading(2) = 5 |
| 0x03 | HAZARD 폭발물·장애물 의심 | 예 | azimuth(2) clock(1) heading(2) = 5 |
| 0x04 | CASUALTY_FOUND 아군 부상자 발견 | 예 | azimuth(2) clock(1) dist_band(1) heading(2) = 6 |
| 0x05 | OK_READY 이상 없음·준비 완료·이동 완료 | 아니오 | 없음 (len=0) |
| 0x06 | WEAPON_AMMO 탄약 부족·화기 문제(사격 곤란) | 예 | 없음 |
| 0x07 | CASUALTY_SELF 본인 부상 | 예 | heading(2) = 2 |
| 0x08 | ACK 수신 확인 | 즉시 | ref_type(1) ref_id(1) = 2 |
| 0x09 | CANNOT_COMPLY 수행 불가 | 즉시 | ref_type(1) ref_id(1) = 2 |
| 0x0A | VOICE_RESULT 음성 수신 결과(자동) | 즉시 | voice_id(1) status(1) = 2 |
| 0x0B | EMCON_STATE 모드 변경 알림 | 아니오 | mode(1) = 1 |
| 0x0C | HEARTBEAT 생존·상태 (v2, 예약) | 아니오 | heading(2) battery_mv(2) heart_rate(1, 0=없음) motion(1, 0=정상 1=무동작) = 6 |
| 0x0D | STATS 송신 통계 (요청 응답) | 아니오 | 모드별 tx_frames(2)×3, tx_bytes(4)×3 = 18 |

필드 설명
- `clock`: 보고 시점 병사 기준 시계 방위 1~12, `0` = 방향 없음. 참고용(분대장 화면 표시). **계산에는 azimuth를 쓴다.**
- `azimuth`: 병사가 계산한 절대 방위 = (heading + (clock−12)×30) mod 360. 방위 정보가 없으면 `0xFFFF`.
- **방위 → 시계 변환 규칙(양측 공통, v1.0.1)**: rel = (azimuth − my_heading + 360) mod 360, clock = (rel + 15) // 30 (정수 나눗셈), 결과가 0이면 12.
  즉 .5 경계는 올림(15도 → 1시, 45도 → 2시). Python의 `round()`는 짝수 쪽으로 반올림하므로 쓰지 않는다.
- `count`: 적 수 1~4, `5` = 5명 이상(다수), `0` = 미상.
- `ref_type`: `0x10` 버튼 명령, `0x11` 음성 명령. `ref_id`: 버튼 명령이면 그 프레임의 seq, 음성이면 voice_id.
- `VOICE_RESULT.status`: `0` 정상 수신·재생 시작, `1` CRC 오류, `2` 수신 시간 초과(청크 누락), `3` 메모리 부족.

### 5.2 분대장 → 병사 (RX Write, 또는 침묵 모드 광고)

| msg_type | 이름 | 연결 모드 | 침묵 모드 | payload |
|---|---|---|---|---|
| 0x10 | CMD_BUTTON 버튼 명령 | O | O | §6 (6바이트) |
| 0x11 | VOICE_BEGIN 음성 시작 | O | X | §7 |
| 0x12 | VOICE_CHUNK 음성 데이터 | O | X | §7 |
| 0x13 | VOICE_END 음성 끝 | O | X | §7 |
| 0x14 | PEER_REPORT 다른 병사 보고 중계 | O | X | reporter_id(1) rx(2,int16) ry(2,int16) + 원 보고 msg_type(1) + 원 보고 payload |
| 0x15 | POS_TABLE 분대 위치·방위 표 | O | X | n(1) + n×[id(1) x(2,int16) y(2,int16) heading(2)] |
| 0x16 | EMCON_SET 모드 지정 | O | O | mode(1) |
| 0x17 | RPT_ACK 보고 수신 확인(자동) | O | X | ref_seq(1) |
| 0x1F | REQ_STATS 통계 요청 | O | X | 없음 |

- 좌표 `x, y`는 **분대장 위치를 원점**으로 한 평면 좌표, 단위 **0.1m**(int16), x = 동쪽, y = 북쪽.
- `PEER_REPORT`: 병사 A의 보고를 분대장이 받아 다른 병사들에게 중계한다. 받는 병사는 A의 위치와 보고 azimuth/dist_band로 표적 위치를 추정하고, 자기 위치·방위로 다시 변환해 재생한다(§9). v1은 분대장 중계, v2는 병사 간 직접 광고.
- `POS_TABLE`: 시연에서는 프리셋 대형 위치를 이 메시지로 병사에게 내려준다. 실전 개념은 RSSI/UWB 상호 거리 + GPS 기준점으로 추정한 결과.
- `RPT_ACK`: 분대장 단말이 병사 보고를 받으면 **자동으로** 보내는 전달 확인(사람의 확인이 아님). 병사는 긴급 보고에 대해 3초 안에 `RPT_ACK`가 없으면 같은 seq로 최대 3회 재전송한다(EMCON 1, 2에서만).

### 5.3 예약·예정 메시지 (v1.0.1 추가)
분대장 단말은 아래 타입을 받으면 **무시하거나 로그만** 남긴다(지금 처리 의무 없음).

| msg_type | 이름 | 방향 | 상태 | payload |
|---|---|---|---|---|
| 0x0E | RANGING 병사 간 RSSI 보고 | 병사 → 분대장 (Notify) | v1.1 예정 | n(1) + n×[peer_id(1), rssi_avg(int8, dBm), samples(1)] |
| 0x20 | BEACON 병사 비콘 | 병사 → 모두 (광고 Manufacturer Data 0xFFFF 안의 프레임, dst 0xFF) | v1.1 예정 | heading(2) |
| 0x7F | LOG 디버그 로그 | 병사 → 분대장 (Notify) | 디버그 빌드 전용 | ASCII 최대 100바이트 |

## 6. 버튼 명령 (CMD_BUTTON, msg_type 0x10)

### 6.1 payload (6바이트)

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0 | 1 | cmd_code | §6.2 |
| 1 | 2 | azimuth | 명령 방향(절대 방위), 없으면 `0xFFFF` |
| 3 | 1 | dist_band | 없으면 `0xFF` |
| 4 | 1 | extra | 코드별(적 수 등), 없으면 0 |
| 5 | 1 | priority | 0 일반, 1 긴급 |

- 대상 병사는 프레임 헤더 `dst_mask`로 지정한다.
- 분대장 단말은 자기 기준 방향(분대장 조이스틱 "몇 시")을 **자기 방위로 절대 방위로 바꿔서** azimuth에 넣는다: azimuth = (leader_heading + (clock−12)×30) mod 360.

### 6.2 명령 코드표

| cmd_code | 이름 | 방향 | 거리 | extra | 병사 이어폰 재생 문장(템플릿) |
|---|---|---|---|---|---|
| 0x01 | HALT 정지 | – | – | – | "정지" |
| 0x02 | TAKE_COVER 엄폐 | 선택 | – | – | "[방향] 엄폐" |
| 0x03 | ADVANCE 전진 | 선택 | – | – | "[방향] 전진" |
| 0x04 | WITHDRAW 후퇴 | 선택 | – | – | "[방향] 후퇴" |
| 0x05 | RALLY 집결(분대장에게) | 자동 | – | – | "[분대장 방향] 집결" |
| 0x06 | OPEN_FIRE 사격 개시 | 필수 | 선택 | – | "[방향] [거리] 사격 개시" |
| 0x07 | CEASE_FIRE 사격 중지 | – | – | – | "사격 중지" |
| 0x08 | OBSERVE 경계 | 필수 | – | – | "[방향] 경계" |
| 0x09 | ENEMY_INFO 적 위치 알림 | 필수 | 선택 | 적 수(0 미상, 5 다수) | "적 [수] [방향] [거리]" |
| 0x0A | REPORT_STATUS 상태 보고하라 | – | – | – | "상태 보고" |
| 0x0B | SILENCE 무선 침묵(병사 EMCON 0 전환) | – | – | – | "무선 침묵" |
| 0x0C | HOLD 현 위치 고수 | – | – | – | "현 위치 고수" |
| 0x0F | CANCEL 직전 명령 취소 | – | – | – | "취소" |

- `RALLY`의 방향은 병사 단말이 POS_TABLE의 분대장 위치(원점)를 향한 방위로 스스로 계산한다. azimuth는 `0xFFFF`로 보내도 된다.
- 병사는 버튼 명령 수신 시 **내장 음성 조각**을 이어 붙여 재생하고(§9.3), LED를 미확인 점멸 상태로 둔다. 병사가 ACK(§8)를 보내면 점멸 종료.

### 6.3 분대장 측 버튼 입력 장치 (권장)
- **권장: 4×4 키패드 1개 + 조이스틱 1개** (아두이노 키트에 키패드가 있으면 사용).
  - 키 13개 = 명령 0x01~0x0C, 0x0F 각 1개 (한 번 누르면 즉시 송신)
  - 키 1개 = 대상 순환(전원 → 1번 → … → 5번 → 전원), 송신 후 전원으로 복귀
  - 키 1개 = 거리 순환(없음 → 근 → 중 → 원)
  - 키 1개 = 적 수 순환(ENEMY_INFO용)
  - 방향 = 명령 키를 누르는 순간의 조이스틱 방향(중앙이면 방향 없음)
- 키패드가 없으면: 버튼 4개 × (짧게/길게) = 8개 명령(HALT, TAKE_COVER, ADVANCE, WITHDRAW, OPEN_FIRE, CEASE_FIRE, RALLY, ENEMY_INFO)으로 축소.
- 분대장 헤드셋 피드백: 송신 직후 "전원 엄폐 송신", 이후 ACK 수신 시 "2번 수신" 등.

## 7. 음성 명령 (연결 모드 전용)

### 7.1 코덱
- **IMA ADPCM, 8000Hz, 모노, 샘플당 4비트** → 4,000바이트/초.
- 한 바이트에 샘플 2개: **하위 니블이 먼저 오는 샘플**, 상위 니블이 다음 샘플.
- 표준 IMA ADPCM 스텝 표(89개)와 인덱스 표(16개)를 그대로 사용한다.
- 인코더 초기 상태(predictor, step_index)는 VOICE_BEGIN에 실어 보낸다. 디코더는 그 값으로 시작한다.
- 주의: Python `audioop`는 Python 3.13에서 제거되었다(UNO Q의 Debian Trixie 기본 Python은 3.13). 분대장 측은 ADPCM 인코더를 직접 구현하거나 `audioop-lts` 패키지를 쓴다. 니블 순서 차이를 막기 위해 **양측이 아래 7.5의 테스트 벡터로 검증**한다.
- 녹음 전처리(분대장 측): 16kHz 이상으로 녹음했다면 8kHz로 리샘플, 앞뒤 무음 제거, 정규화(최대 −3dBFS).

### 7.2 전송 방식: 발화 단위 저장 후 재생 (v1)
- 분대장이 PTT(누르고 말하기)로 한 발화를 녹음 → 인코딩 → BEGIN, CHUNK들, END 전송 → 병사는 END에서 CRC 확인 후 재생.
- 최대 길이 **10초**(40,000바이트). 넘으면 분대장 측에서 잘라 여러 voice_id로 나눈다.
- 실시간 스트리밍(받으면서 재생)은 v2.

### 7.3 payload

**VOICE_BEGIN (0x11)**

| 크기 | 필드 | 설명 |
|---|---|---|
| 1 | voice_id | 0~255 순환 |
| 1 | codec | `0x01` = IMA ADPCM 4bit |
| 2 | sample_rate | 8000 |
| 4 | total_samples | 총 샘플 수 |
| 2 | total_chunks | 총 청크 수 |
| 2 | predictor | int16 초기 예측값 |
| 1 | step_index | 0~88 |
| 1 | priority | 0 일반, 1 긴급(재생 중인 음성을 끊고 바로 재생) |
= 14바이트

**VOICE_CHUNK (0x12)**

| 크기 | 필드 |
|---|---|
| 1 | voice_id |
| 2 | chunk_idx (0부터) |
| N | ADPCM 데이터 |

- N = (MTU − 3) − 헤더 6 − 3. MTU 247이면 **N = 235**. 마지막 청크만 짧을 수 있다.
- 분대장 측은 청크 사이에 약 10~20ms 간격을 두어 병사 버퍼가 넘치지 않게 한다(실측 후 조정).

**VOICE_END (0x13)**

| 크기 | 필드 | 설명 |
|---|---|---|
| 1 | voice_id | |
| 2 | crc16 | ADPCM 데이터 전체(청크 순서대로 이어 붙인 바이트)에 대한 CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF, 반사 없음, xorout 0) |

### 7.4 병사 처리
1. BEGIN 수신 시 버퍼 할당(최대 40,000바이트). 실패하면 `VOICE_RESULT status=3`.
2. CHUNK를 chunk_idx 위치에 기록, 받은 청크 수 기록.
3. END 수신 시 누락 청크가 있으면 `status=2`, CRC 불일치면 `status=1`, 정상이면 `status=0`을 보내고 재생 시작.
4. (v1.0.2 변경) **마지막으로 받은 BEGIN 또는 CHUNK 이후 3초 동안** 다음 프레임이 없으면 폐기하고 `status=2`(무활동 기준). 이전 판의 "BEGIN 후 3초"는 긴 발화나 느린 송신 측에서 정상 전송도 시간 초과가 될 수 있어 변경. 분대장 측 구현에는 영향 없음.
5. 분대장은 `status≠0`이면 같은 voice_id로 전체를 1회 재전송한다.
6. 재생이 끝나면 LED 미확인 점멸 → 병사가 ACK(ref_type=0x11, ref_id=voice_id).
7. 조이스틱 짧게 누르기로 마지막 음성을 다시 들을 수 있다(송신 없음).

### 7.5 테스트 벡터 (양측 공통 검증)
- 입력: 8kHz 1초 사인파 440Hz, 진폭 8000, int16. 샘플 i = round(8000·sin(2π·440·i/8000)).
- predictor=0, step_index=0에서 인코딩한 결과의 **처음 16바이트(hex)와 전체 CRC16**을 분대장 측이 먼저 계산해 이 문서 부록에 적는다. 병사 측 디코더/분대장 측 인코더는 이 값으로 상호 검증한다.

## 8. 수신 확인 흐름

### 8.1 분대장 명령에 대한 병사 확인(사람)
1. 분대장 → 병사: CMD_BUTTON(seq=s) 또는 음성(voice_id=v).
2. 병사 이어폰 재생, LED 미확인 점멸.
3. 병사 버튼3 짧게 → `ACK(ref_type, ref_id)` / 버튼3 길게 → `CANNOT_COMPLY(ref_type, ref_id)`.
4. 분대장 헤드셋: "2번 수신" / "2번 수행 불가".
5. 분대장 측: 15초 안에 대상 병사 ACK가 없으면 같은 명령을 **같은 seq로** 1회 재전송, 그래도 없으면 "3번 미수신" 알림.
6. 병사 측: 같은 (src_id, seq) 명령을 다시 받으면 다시 재생하되 새 명령으로 취급하지 않는다.
7. 침묵 모드: 병사 ACK는 큐에 저장, 분대장은 ACK를 기다리지 않는다.

### 8.2 병사 보고에 대한 단말 자동 확인
- 분대장 단말은 보고 수신 즉시 `RPT_ACK(ref_seq)` 송신.
- 병사는 긴급 보고(0x01, 0x03, 0x04, 0x06, 0x07)에 한해 3초 내 RPT_ACK가 없으면 최대 3회 재전송.

## 9. 병사 단말 동작 상세

### 9.1 입력 배치 (최종)
원칙: **조이스틱 = 어디(방향·거리), 버튼 = 무엇.** 모든 보고는 "기울이고 누르기" 최대 2동작.

시간 기준: 짧게 < 0.6초, 길게 ≥ 1.0초(본인 부상만 ≥ 2.0초), 두 번 = 0.4초 안에 다시 누름.

| 입력 | 동작 | 송신 메시지 |
|---|---|---|
| 조이스틱 기울인 채 **버튼1**을 N번(1.2초 안에 연속) | 적 발견, 적 N명(5번 이상 = 다수). 마지막 입력 후 1.2초 뒤 송신 | CONTACT |
| 조이스틱 기울인 채 **버튼2 짧게** | 의심 징후 | SUSPICIOUS |
| 조이스틱 기울인 채 **버튼2 두 번** | 아군 부상자 발견 | CASUALTY_FOUND |
| 조이스틱 기울인 채 **버튼2 길게** | 폭발물·장애물 의심 | HAZARD |
| **버튼3 짧게** | 마지막 명령 수신 확인 | ACK |
| **버튼3 길게** | 마지막 명령 수행 불가 | CANNOT_COMPLY |
| **버튼4 짧게** | 이상 없음·준비 완료·이동 완료 | OK_READY |
| **버튼4 두 번** | 탄약 부족·화기 문제 | WEAPON_AMMO |
| **버튼4 길게(2초)** | 본인 부상 | CASUALTY_SELF |
| **조이스틱 짧게 누름** | 마지막 수신 명령 다시 듣기 | 없음(로컬) |
| **조이스틱 길게 누름(1초)** | 방출 모드 순환 0→1→2→0 | EMCON_STATE(모드 1/2 진입 시) |
| **버튼1+버튼4 3초** | 방위 센서 보정 모드 | 없음 |

조이스틱 해석
- 방향: 중앙 보정값 기준 atan2 → 시계 1~12(12 = 총구 전방). 기울기 35% 미만 = 방향 없음(clock=0, azimuth=0xFFFF).
- 거리: 기울기 **35~75% = 근거리(0)**, **75% 이상 = 원거리(2)**. 중거리(1)는 병사 입력에서 쓰지 않는다(분대장 명령에서만 사용).
- 방향 없이 버튼1을 누르면 "적 발견, 방향 미상"으로 송신.

### 9.2 로컬 음성 피드백(송신 없음)
- 버튼1 누를 때마다 숫자("1", "2"…), 송신 시 "적 발견 송신", 징후류는 "징후 송신" 등 짧게.
- 모드 변경 시 "침묵" / "최소" / "정상".
- RPT_ACK 수신 시 짧은 확인음 1회(긴급 보고만).

### 9.3 수신 명령 재생과 방향 변환
- 버튼 명령: azimuth를 자기 기준으로 변환 → clock = round(((azimuth − my_heading + 360) mod 360) / 30), 0이면 12. 재생 예: "9시 엄폐".
- PEER_REPORT(다른 병사 보고): 표적 추정 위치 T = 보고자 위치 + d·(sin az, cos az) (d = 거리 대표값, 거리 없으면 100m 가정). 내 위치 P에서 T로의 방위 b와 거리 r을 구해 clock과 거리 구간으로 재생: "적 3, 2시, 근거리".
- 내장 음성 조각 목록(PCM 또는 ADPCM, 8kHz):
  - 숫자: 1, 2, 3, 4, 다수, 미상
  - 방향: 1시 ~ 12시
  - 거리: 근거리, 중거리, 원거리
  - 명령: 정지, 엄폐, 전진, 후퇴, 집결, 사격 개시, 사격 중지, 경계, 상태 보고, 무선 침묵, 현 위치 고수, 취소
  - 보고/공유: 적, 징후, 폭발물 의심, 부상자, 아군
  - 시스템: 송신, 수신, 침묵, 최소, 정상, 보정 시작, 보정 완료
- 1단계 개발에서는 재생할 문장을 BLE 로그나 노트북으로 넘겨 노트북이 재생해도 된다. 문장 템플릿은 위와 동일하게 유지.

### 9.4 LED
- LED1: 연결 상태(연결 = 켜짐, 침묵 스캔 = 3초마다 짧게).
- LED2: 미확인 명령 있음 = 점멸.
- LED3: 송신 순간 짧게.
- LED4: 모드 표시(0 = 꺼짐, 1 = 느린 점멸, 2 = 켜짐).

## 10. 분대장 단말 동작 요약 (분대장 담당용)

1. 병사 `SQ1-S1`~`S5` 스캔·연결, NUS TX Notify 구독, MTU 확인.
2. 병사 보고 수신 → 즉시 RPT_ACK → 분대장 헤드셋 문장 재생 + 저장(소대장 보고용) → 필요 시 다른 병사들에게 PEER_REPORT 중계.
3. 분대장 헤드셋 재생 문장 템플릿(병사 보고):
   - CONTACT: "[n]번, 적 [수], [분대장 기준 방향], [거리]"
   - SUSPICIOUS: "[n]번, 징후, [방향]"
   - HAZARD: "[n]번, 폭발물 의심, [방향]"
   - CASUALTY_FOUND: "[n]번, 부상자 발견, [방향]"
   - OK_READY: "[n]번, 이상 없음"
   - WEAPON_AMMO: "[n]번, 탄약 화기 문제"
   - CASUALTY_SELF: "[n]번 부상" (최우선, 반복 2회)
   - ACK / CANNOT_COMPLY: "[n]번 수신" / "[n]번 수행 불가"
4. 음성 명령: PTT 녹음 → ADPCM → 대상 병사 각각에 BEGIN/CHUNK/END → VOICE_RESULT 확인 → ACK 대기.
5. 버튼 명령: 키 입력 → CMD_BUTTON. 연결 모드면 각 병사에 write, 침묵 모드면 광고 3초.
6. 모드 지정: 분대 전체를 침묵으로 만들 때는 먼저 연결 모드로 `EMCON_SET(0)` 또는 CMD_BUTTON `SILENCE`를 보내고, 이후 연결을 끊고 광고로 전환한다.

## 11. 시험 절차

### 11.1 병사 단말 단독 (nRF Connect 모바일 앱)
1. `SQ1-S1` 연결 → TX Notify 구독.
2. RX에 아래 hex 쓰기(Write Request):
   - 전원 엄폐, 방위 270, 근거리 아님, 긴급
     `01 10 05 00 1F 06 02 0E 01 FF 00 01`
     (ver 01, CMD_BUTTON 10, seq 05, src 00, dst 1F, len 06 | cmd 02, az 0x010E=270, dist FF, extra 00, prio 01)
   - 병사 1번에게 적 위치 알림, 방위 45, 원거리, 3명
     `01 10 06 00 01 06 09 2D 00 02 03 00`
   - 상태 보고 요청: `01 1F 07 00 01 00`
3. 병사가 내야 하는 보고 예(병사 1, seq 7, 적 3명, 시계 2, 원거리, 내 방위 0 → azimuth = 60):
   `01 01 07 01 80 07 3C 00 02 02 03 00 00`
   (v1.0.1 수정: 이전 판의 azimuth 45(0x2D)는 §5.1 공식과 맞지 않아 60(0x3C)으로 정정)

### 11.2 분대장 단말 단독
- 병사 단말 대신 Python 모의 병사(bleak로는 Peripheral을 만들기 어려우므로, 분대장 로직을 "프레임 인코더/디코더 + 전송 인터페이스"로 분리해 메모리 큐로 테스트)를 사용.
- 프레임 인코드/디코드는 이 문서 §11.1의 hex와 바이트 단위로 일치해야 한다.

### 11.3 통합 순서
1. 연결 + 버튼 명령 + ACK
2. 병사 보고 + RPT_ACK + 분대장 헤드셋 문장
3. 음성 명령(짧은 2초 발화부터)
4. 침묵 모드 광고 수신
5. PEER_REPORT / POS_TABLE 기반 방향 변환

- v1 (해커톤): 위 전체. 병사 간 직접 통신은 분대장 중계(PEER_REPORT)로 대체. 위치는 POS_TABLE 프리셋.
- v2 (설계만): 병사 간 직접 광고 + 상호 RSSI(실전은 UWB) 기반 위치 추정, 실시간 음성 스트리밍, HEARTBEAT(심박·무동작), 메시지 인증(HMAC).

## 부록 A. ADPCM 테스트 벡터 (v1.0.1 확정, 병사 측 C/Python 구현으로 생성·교차 검증)
- 조건: 440Hz 사인파, 진폭 8000, 8kHz, 1초(8000샘플), 샘플 i = round(8000·sin(2π·440·i/8000)), 초기 predictor = 0, step_index = 0, 하위 니블 먼저
- 출력 길이: 4000바이트
- 처음 16바이트: `70 77 77 77 F1 BB 9B 18 44 53 22 82 B8 CC AC 9B`
- 전체 CRC16 (CRC-16/CCITT-FALSE): `0x0166`
- 참고: Python 3.12의 `audioop.lin2adpcm` 결과와 니블 순서만 다르고 동일함을 확인(audioop은 상위 니블 먼저). 분대장 측 인코더가 이 값과 일치하면 호환.
